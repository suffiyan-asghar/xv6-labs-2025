q2) Is there a way to eliminate the special TRAPFRAME page mapping in every user address
 space? For example, could uservec be modified to simply push the 32 user registers onto
 the kernel stack, or store them in the proc structure?
ans) The trapframe page mapping, which stores the registers of the user process during a trap, is essential because RISC-V hardware does not switch page tables when a trap occurs from user space. The trap handler code, uservec, begins execution immediately using the user’s current page table. To safely store the 32 user registers in the process's trapframe structure, the virtual address (TRAPFRAME or 0x3fffffe000) used for this must resolve correctly within the active user page table. If uservec were modified to push registers onto the kernel stack or into the kernel’s proc structure (located at high kernel virtual addresses), these memory accesses would fail, as these kernel addresses are typically not mapped in the user page table, causing an exception or panic. Therefore, the dual mapping of TRAPFRAME (shared by both user and kernel page tables) is crucial for saving the state before the operating system transitions to its full kernel environment.

q3)  Could xv6 be modified to eliminate the special TRAMPOLINE page mapping?

ans) The trampoline page is necessary because, like the trapframe, the entry point of the trap handler specified by stvec must be mapped in the user page table, as RISC-V hardware does not switch page tables when a trap occurs. However, the need for this specialized trampoline mapping could be removed if the kernel were modified to map all kernel memory into every user process's page table. This mapping would need to be restricted from user access (by clearing the PTE_U flag), enabling the kernel's trap entry point to execute directly under the user page table without a separate trampoline address space. xv6 avoids this approach to improve memory isolation and reduce the risk of security vulnerabilities from accidental or unintentional use of user pointers. Instead, it uses the simpler, isolated solution of the dual-mapped trampoline page.
